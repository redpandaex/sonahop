# 首版音频实施计划

> 使用 superpowers:subagent-driven-development，按明确文件边界并行实施；用户授权执行且选择自行测试，测试步骤交由用户。

**Goal:** 交付 Windows 系统声音→两台 Android，以及一台 Android 麦克风→Windows 既有虚拟端点。
**Architecture:** sonahop-link 负责认证/加密连接；sonahop-audio 提供 Opus 和二进制媒体包；Windows 与 Android 平台适配 I/O；Tauri AudioService 负责模式互斥和生命周期，React 显示真实状态。
**Spec:** docs/superpowers/specs/2026-10-12-audio-mvp.md

## Global Constraints
- 仅 Windows 11 / Android 16，模式分开运行；不可自动开启麦克风。
- 使用 CLI 添加依赖；用户自行运行测试和构建验证。
- 不更改电脑音量、输出路由、防火墙和系统驱动。

## Tasks
- [x] Windows: SystemCapture::new() 实现 AudioCapture，48k stereo f32；AudioOutput::new(device_id)、write(samples,timeout) 返回已写入样本数。
- [x] Link: protocol v2 / PIN / SPAKE2 / AES-GCM；LinkEvent、subscribe()、send_control()、send_media()，有界媒体队列。
- [x] Android: 音频权限、foreground service、JNI PCM、录放线程和停止/焦点生命周期。
- [x] Shared codec: Opus 20ms，有界包验证、流 ID 和 sequence。
- [x] Tauri: Arc<LinkService>、AudioService、音频七个命令；模式互斥、virtual output、断开停止。
- [x] UI: 输入连接码、双端开始/停止/等待状态、麦克风授权与输出选择、独立手机增益。
- [x] Handoff: 更新 README/AGENTS，构建命令和 Android symlink 权限兼容脚本，手测步骤。

## Review Focus
- 两个连接与只允许一个麦克风；被拒绝的连接不得传输音频。
- 服务停止/断开/切换/通知停止释放 I/O，旧 generation 不可覆盖新状态。
- 静音和无数据包、过大包、乱序、慢网络不会积压无限延迟。
- 未安装虚拟驱动清晰提示并等待用户指定。
- Android 运行时权限拒绝/后台 FGS 禁止/音频焦点丢失传播实际错误。
