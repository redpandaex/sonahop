# Windows 与 Android 界面阶段

## 意图与范围
用户要求先完成 Windows 和 Android 可视化界面，再继续音频链路。沿用 Rust 核心、Tauri、React/TypeScript。
最终目标保持双 Android 收听、单 Android 麦克风与收听互斥；手机独立控制音量，电脑静音仍可收听。首轮真机选择联想 Y700 四代 / Android 16。

本阶段交付可启动的 Windows GUI 和可安装的 ARM64 Android 调试 APK。
Windows 接入现有真实播放设备枚举；两端的模式、音量、主题和连接信息编辑可以交互并保存。
当前音频连接尚未接入，界面明确标记预览；不能伪造已连接、正在播放、麦克风权限或实时测量。

## 布局
- 共用一套暖白、深色文字、细分隔线与淡绿状态色；提供浅色/深色/系统主题。
- Windows 为侧栏 + 音源工作区 + 接收设备区，真实设备可刷新与选择。
- Android 为单列连接和播放控制；平板利用额外宽度，窄屏不出现横向溢出。
- 收听和麦克风为互斥模式；当前相关启动动作不可用，并给出版本能力说明。
- 手机音量设置表示独立播放增益的偏好；此阶段不修改系统音量，不宣称音量独立的音频路径已验收。
- 未连接时显示空状态与静止信号，不生成假设备、假电平或假延迟。
- 设置保存主题、模式、音量与电脑地址；地址仅保存，不触发连接或配对。
- 使用语义控件、键盘焦点与可读对比度；尊重减少动态效果设置。

## 工程
- 根 pnpm workspace 只纳入 apps/sonahop-ui，官方 create-tauri-app 初始化 React/TypeScript。
- apps/sonahop-ui/src-tauri 纳入现有 Cargo workspace；共享核心保持独立。
- Rust get_app_info 返回平台、版本与界面预览标志。
- Rust list_playback_devices 仅在 Windows 枚举；在阻塞工作线程上初始化/释放 MTA，不能在 WebView 的 STA 线程调用。
- 前端拆分桌面/Android 屏幕、共用控件、平台桥接、偏好与样式。浏览器预览显式标记示例，原生桥接失败不得假装成功。
- 未引入网络、音频播放/录音服务、驱动和麦克风权限。
- 依赖和脚手架通过 CLI；仅手工编辑 CLI 未覆盖的 workspace 连接和应用代码。

## 验收
1. Windows 原生 GUI 启动并显示真实播放设备，选择/刷新/模式/主题操作可用。
2. 前端构建及偏好边界测试通过；360×800 手机、800×1280 平板和桌面布局经浏览器实际检查。
3. ARM64 Android 调试 APK 构建成功。Y700 已连接时安装/打开并截图验证；未连接则提供 APK，明确真机待办。
4. 现有 Rust 测试、格式和 Clippy 不回退；一次独立分支审查，修复重要问题。
5. 交付根目录启动命令、Windows exe、APK 与截图。未经请求不推送或发布。

## 已有证据
Windows 采集已由用户手动播放歌曲验证；读取最新 WAV 得到 48kHz、双声道、20 秒、波形峰值约 0.925，所有 1920000 个样本非零。
这个结果证明默认 G24H2 端点实际读出了声音，不能替代音量独立、Android、后台及网络验收。

## 实现顺序
先 CLI 建立 Tauri 和只读桥接；再完成共享交互与两个布局；随后构建/查看原生 Windows 与 Android；最后审查并交付。
用户已要求实现，本轮保留上一阶段的直接执行方式；普通实现选择不重复征求过程批准。
