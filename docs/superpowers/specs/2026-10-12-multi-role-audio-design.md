# 跨平台服务器与播放器设计 — 2026-10-12

用户已授权实现：Android 可作为服务器，Windows 与另一台 Android 能同时发现并收听；Windows 服务器也可选择本机播放声音或麦克风。两种音源分别选择，不自动混音。UI 重构为服务器、播放器、设置，保留现有风格。

## 边界
- 连接角色 host/client 与 Windows/Android 分离；每个实例一次一个角色，默认 Windows host、Android client。切换角色先停止音频和连接。
- 音源 system/microphone 独立选择。平台工厂根据能力构造采集或播放后端；协议、Opus、加密和连接管理继续复用。
- 服务器最多连接两个播放器。Windows 与 Android 播放器都接收 Listen 流，输出至本机扬声器/耳机，不修改 OS 默认设备或音量。
- Android 服务器采集麦克风或内部播放声音；内部声音使用 AudioPlaybackCapture 和用户明确授予的 MediaProjection，不请求音频焦点打断被采集应用，不捕获 SonaHop 自己。
- Windows 服务器继续使用进程系统采集，新增本机录音设备采集。无可用录音设备时禁用麦克风音源。
- Windows 服务器原有接收一台远端麦克风、输出到用户选择的虚拟音频线仍保留；Android 服务器不提供这项 Windows 虚拟录音功能。
- 不加入虚拟驱动、手机混音、自动录音、自动重连录音或网状连接。

## 界面
- 一级入口为服务器、播放器、设置。服务器显示音源、开始共享、PIN、审批与已连接设备；播放器显示发现、配对、手动地址和本地播放控制。
- 连接面板使用服务器/设备措辞，不按平台写死电脑/手机。Windows 播放器可选择本应用的播放出口。
- 源选择在共享时禁用；停止后切换并重新开始。连接恢复与音频恢复仍由用户操作。
- Windows 服务器保留远端麦克风区域；播放器在对端支持时保留申请上传本机麦克风入口。
- 保留浅色/深色、品牌图标、可访问的键盘焦点和小屏适配。预览状态不得显示虚假连接或音频支持。

## 验收
Android 服务器分别共享音乐与麦克风，Windows 和 Y700 同时接收；Windows 服务器现有系统共享不回归，本机麦克风存在时可以共享；角色切换停止旧会话，拒绝/撤销捕获授权正确退出。音频、设备和自动测试由用户进行，本轮仅最终编译打包与文件签名检查。
