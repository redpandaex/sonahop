# VB-CABLE 与同时收发设计

用户已选择复用现成虚拟音频设备，自研虚拟 Speaker/Mic 驱动暂停。此前驱动源码/WDK任务由本方案替代，不作为本轮交付要求。

Windows 使用已有 WASAPI AudioOutput 写入用户明确选择的虚拟音频线播放端。VB-CABLE 的 CABLE Input/Output（含 A/B/C/D）及 Voicemeeter 的对应入口/录音端按已枚举名称识别；它是用户界面的推荐提示，不宣称验证了任意驱动的内部实现。已知录音端缺失时禁用启用按钮；同名或改名端点不自动配对；可通过显式高级选择手动配置播放和录音设备 ID，并由用户确认对应关系，录音端失效时禁用启动。

Windows 收听页增加“扬声器/耳机”和“电脑麦克风”接收目的，独立保存输出偏好。共享页接收远端麦克风复用同一个虚拟入口选择与指南。无已安装设备时提供折叠安装说明和 VB-Audio 官网链接，不自动下载、安装、创建驱动或更改系统默认设备。

已有同时收发改动保留：Android 一条采集会话和一条播放会话独立，Windows 主动批准远端麦克风时保留收听订阅。方向切换仅切换操作视图；角色切换、断连接、通知停止仍停止全部。Windows 共享和远端麦克风不混音。

主程序独立发布 exe 和按当前用户安装的 NSIS 安装器；Android 保留原 debug 签名更新。虚拟驱动为外部可选组件。本轮只编译、打包及静态复核，用户执行音频与真机验收。
